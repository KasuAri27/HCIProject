# 学习前问卷（计算机相关）

分两段收集，都不做考试测评。

1. **入学时**：只问计算机基本功 + 目标/节奏，用来生成学习路径与课程规划（建议，不强绑）。
2. **进入某一门课/某一章时**：按该课原文，用下方 LLM 模板生成「相关基础」询问。

统一自评档位：

| 档位 | 含义 | 规划时怎么用 |
|------|------|----------------|
| 不会 | 没学过或几乎没用过 | 建议补，作为前置 |
| 了解 | 看过、能说出概念 | 建议浏览/补漏，不从头精读 |
| 能用 | 写过、跑过、调过 | 基础可跳，留进阶章 |
| 熟悉 | 能讲原理、排过坑 | 默认建议跳过，除非用户要求留下 |

最少需要「能力自评 + 目标」才能生成规划；节奏未填时默认：中等时长、先通再回头。

## 四、进入课程时的基础询问（LLM 模板）

用户打开某一门课/某一章原文、开始阅读之前，用本章内容和入学问卷，生成一组**相关基础**问题。不问本章将要教的新知识。

将下面整段作为 system/指令发给 LLM，再填入占位内容。

```
你是 AI Infra 学习助手。用户即将开始阅读「当前课程原文」。
请根据原文，列出学习这一份内容之前应当具备的前置基础，并生成简短自评问卷。

必须遵守：
1. 只问「学这一章之前就该有的基础」，不要问本章将要讲的新概念本身。
   反例：原文在讲 FlashAttention，不要问「你会不会 FlashAttention」。
   正例：可以问 tiling、softmax 数值稳定、GPU 存储层次等原文会用到的前置。
2. 先看【入学问卷】。已经问过且粒度足够的，不要重复。
   入学问卷只有粗项（语言/STL/架构/需求/网络/OS）时，允许针对本章补问更具体的点
   （例如：矩阵乘法直觉、PyTorch Tensor、进程 vs 线程、TCP 与 RDMA 的差别）。
3. 题目 2～5 道；若本章几乎不需要额外基础，输出 0 道并说明「无需补问」。
4. 每题必须用四档：不会 / 了解 / 能用 / 熟悉。不要改成考试题、计算题或开放问答题。
5. 每题包含：简短题干、为何这一章需要它（不超过一句）、对应四档选项。
6. 用简体中文。不要讲解原文、不要总结全文、不要推荐学习路径、不要输出与问卷无关的内容。
7. 用户若在入学问卷里已勾选跳过与本章对应的模块，仍生成问卷，但在开头用一句话提醒：
   「你计划跳过相关模块，下列问题用于确认缺口，可快速全选不会。」

输出格式（严格）：
- 先一行：本章前置焦点：……（不超过 20 字）
- 然后每题：
  Qn. <题干>
  为何需要：<一句>
  选项：不会 / 了解 / 能用 / 熟悉

【入学问卷】
（身份、年限、掌握语言及档位、STL、常用架构、需求工程、计算机网络、OS、学习目标、节奏、跳过项、选填）

【当前课程】
标题：
原文：
```

询问结果只作用于**当前这一课**：决定要不要先补一小段前置说明、阅读时是否放慢，不自动改写整份入学规划。换章则按新原文重新生成询问（可复用用户已答过的相同前置题，不必重复点选）。

## 规划时怎么用（粗规则）

入学问卷只决定大方向；具体会不会 CUDA / 推理等，以进课询问为准。

- **路径**：按目标 + 跳过项建议先读哪一层、哪些浏览、哪些跳过
- **课程规划**：精读还是快通、面试是否插入、按每周时长控制一阶段不要太满；基本功偏弱（语言/OS/网络多为「不会/了解」）则第零层放慢、说明写细
- **起点**：默认打开建议的第一章，目录仍可点任意章
- **进课询问**：只调整这一课的阅读方式（补前置提示 / 正常读 / 可较快），不推翻用户已确认的路径

粗规则：

- 语言、OS、网络偏弱 → 从第零层起，系统向章节标「可先补基础」
- 基本功能用以上、目标是系统入门 → 仍按四层顺序推荐，但可标部分浏览
- 目标是工程实践 → 按跳过项压深度；未跳过的层仍建议过
- 目标是面试 → 路径里加面试板块，精读对准各层检验标准
- 勾了跳过某模块 → 规划标建议跳过，进该模块课程时仍用模板补问缺口

本次入学不收集：非计算机背景、学校课程名、论文/公司项目、课程专题掌握程度（进课时再问）。
